    Per D-20, D-21, D-33, D-35:

    For EACH generator (Python, C#, Lua, JS, C++), extend the `rust_type_to_*` conversion to detect function pointer types:

    1. DETECT fn ptr patterns in the rust_type string from `type_to_string()`:
       - The compact `quote!()` output looks like: `unsafeextern"C"fn(*constHostInterface,*constPluginDescriptor,*constGuestContractInterface)->AbiError`
       - Also handle: `Option<unsafeextern"C"fn(...)>` -- the Option wrapper means nullable
       - Parse by finding `extern"C"fn(` or `extern\"C\"fn(` as the delimiter, then extract parameter types between `(` and `)`, then return type after `)->`

    2. PYTHON generator (python.rs):
       - When a field's rust_type contains an extern "C" fn pattern, emit a CFUNCTYPE typedef BEFORE the struct that contains it.
       - Pattern: `_typename_fn_ptr = ctypes.CFUNCTYPE(return_type, param1_type, param2_type, ...)`
       - Map fn ptr params using existing `rust_type_to_python()` for each parameter.
       - For `Option<fn ptr>`, still emit CFUNCTYPE but the field uses the CFUNCTYPE type (ctypes allows None for callback types).
       - For Array<T> (rust_type contains `Array`), emit: `("items", ctypes.c_void_p), ("len", ctypes.c_size_t), ("align", ctypes.c_size_t)` per D-21.
       - For tuple types like `(u32, u32)`, emit a small ctypes.Structure or use c_uint64 packing.
       - Name convention: snake_case (per D-35, keep as-is).

    3. C# generator (csharp.rs):
       - When a field's rust_type contains an extern "C" fn pattern, emit a delegate definition BEFORE the struct.
       - Pattern: `[UnmanagedFunctionPointer(CallingConvention.Cdecl)] public delegate ReturnType FieldNameDelegate(param1Type param1, ...);`
       - For `Option<fn ptr>`, the delegate type is nullable by default (reference type).
       - For Array<T>, emit: `public IntPtr items; public nuint len; public nuint align;`
       - Name convention: PascalCase (per D-35).

    4. LUA generator (lua.rs):
       - When a field's rust_type contains an extern "C" fn pattern, emit a typed function pointer typedef in the ffi.cdef block.
       - Pattern: `typedef ReturnType (*FieldNameFn)(param1Type, param2Type, ...);` then use `FieldNameFn field_name;` in the struct.
       - For `Option<fn ptr>`, use `FieldNameFn field_name;` (LuaJIT FFI allows NULL for fn ptr fields).
       - For Array<T>, emit: `void* items; size_t len; size_t align;`
       - Name convention: snake_case (per D-35).

    5. JS generator (js.rs) -- Per D-33, emit BOTH:
       - TypeScript interface with typed fields (for type checking)
       - Binary offset constants as `export const STRUCT_NAME_FIELD_OFFSET: number = N;` for DataView access
       - For fn ptr fields: emit as `number` in the interface (offset into struct memory)
       - For Array<T>: emit as `{ items: number; len: number; align: number }` or similar
       - Name convention: camelCase for interfaces/methods, UPPER_SNAKE_CASE for offset constants (per D-35).
       - Per D-34: target Deno host only.

    6. C++ generator (cpp.rs):
       - When a field's rust_type contains an extern "C" fn pattern, emit a typedef before the struct.
       - Pattern: `typedef ReturnType (*FieldNameFn)(param1Type, param2Type, ...);` then use `FieldNameFn field_name;` in the struct.
       - For `Option<fn ptr>`, use `FieldNameFn field_name; /* nullable */`
       - For Array<T>, emit: `void* items; size_t len; size_t align;`
       - Name convention: snake_case in `polyplug` namespace (per D-35).

    Each generator should add a helper function like `convert_function_pointer(rust_type: &str) -> Option<FnPtrInfo>` that parses the compact fn ptr string and returns structured data (return type, param types list). This function returns None if the rust_type is not a fn ptr, and the existing rust_type_to_* handling continues as before.

    ADD a validate_representation method or check inside generate_struct that returns an error string for types that cannot be represented. Per D-09: complex generic bounds (`dyn `, `impl `, `for<`, `where `) should cause the generator to return an error. Simple types (primitives, pointers, known structs, Option, Array, tuples) are fine.
