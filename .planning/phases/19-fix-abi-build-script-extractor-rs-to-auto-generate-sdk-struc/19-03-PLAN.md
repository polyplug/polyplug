<objective>
Implement ast-grep integration for preserving hand-written helper method bodies across code regenerations, and set up the generated file structure with helper file merging.

Purpose: When the build script regenerates abi.* files, any hand-written helper methods (like StringView.from_ptr(), StringViewHelper.StripPrefix()) would be lost. ast-grep extracts these method bodies from existing files and splices them into the fresh generated output.

Output: Build script pipeline that: generates fresh code, runs ast-grep to preserve method bodies, writes merged output. Helper files merged into abi.* files.
</objective>

       a) READ helper files that need merging (per D-12):
          - C#: Read StringViewHelper.cs and StringHelpers.cs from `sdks/csharp/abi/`

          - Use `std::process::Command` to call `sg scan` with inline rules.
          - For each language, define a pattern rule that matches method definitions.
          - Parse the JSON output to extract method names and their full body text.
          - For Lua specifically (ast-grep has limited Lua support per research), use a simple regex-based extractor: look for `function\s+[\w.]+\(` patterns.

The function is small (~30 lines, handles snake_case/PascalCase/camelCase bidirectional conversion).

       e) DELETED METHOD HANDLING (per D-15):
          - For methods found in old file but NOT matching any generated class, prefix with `DELETED_`.
          - Append these at the end of the file as comments or inactive code.
          - sdk_validator will fail CI if `DELETED_` prefix found (existing behavior).

       f) DO NOT clean up FFI function calls (per D-16) -- that is a manual one-time fix.

       - Per D-13: C++ writes to `sdks/cpp/abi/polyplug/abi.hpp`.
       - Delete the now-merged helper files after successful merge.
