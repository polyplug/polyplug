**Objective:** Update generator templates to produce code matching the current ABI structure, fixing the compilation errors in generated code.

### Task 1: Fix Rust Generator ABI Templates

<read_first>
- crates/polyplugc/src/generators/rust.rs
- crates/polyplug_abi/src/plugin/plugin_descriptor.rs
- crates/polyplug_abi/src/error.rs
- crates/polyplug_abi/src/guest/guest_contract_interface.rs
</read_first>

<action>
Fix the following ABI mismatches in rust.rs:

1. PluginDescriptor version fields (lines ~63-69 in init.rs generation):
   - CHANGE: `version_major: 1_u32, version_minor: 0_u32, version_patch: 0_u32`
   - TO: `version: Version { major: 1, minor: 0, patch: 0 }`

2. Error code constants (throughout):
   - CHANGE: `ABI_ERROR_GENERIC` (u32 constant)
   - TO: `AbiErrorCode::GenericError as u32` or use `AbiError::generic()` helper

3. Registration function name (line ~72):
   - CHANGE: `(host.register_plugin)(rt_ctx, ...)`
   - TO: `(host.register_contract)(rt_ctx, ...)`

4. GuestContractInterface fields (lines ~91-102 in vtables.rs generation):
   - REMOVE: `rt_ctx: core::ptr::null()` (field does not exist)
   - KEEP: `contract_id`, `contract_version`, `function_count`, `dispatch_type`, `dispatch`
   - Note: The actual struct uses `to_guest_instance` and other instance-related fields

5. Import statement fixes:
   - Ensure imports use `GuestContractInterface` (polyplug_guest still provides alias)
   - Ensure imports use `RuntimeAbi` (polyplug_guest still provides HostInterface alias)

6. Read the actual GuestContractInterface struct definition to verify correct fields.
</action>

<acceptance_criteria>
- Generated init.rs uses `version: Version { major, minor, patch }` pattern
- Generated init.rs uses `register_contract` function
- Generated vtables.rs does NOT have `rt_ctx` field
- Generated code uses `AbiErrorCode::*` instead of `ABI_*` constants
- `cargo build -p polyplugc` exits with code 0
</acceptance_criteria>
